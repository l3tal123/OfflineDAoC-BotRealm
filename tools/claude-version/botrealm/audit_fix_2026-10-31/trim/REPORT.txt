TRIM OF OVER-DENSE RESTORED SPAWN GROUPS (spawns agent, owner-approved rule, 2026-10-31)

Rule: in every restored monster+zone group that has CapnBry radar data, live (pre-existing, non-restored) + restored
spawns must not exceed ceil(clusters * 1.15). Clusters = distinct CapnBry sighting positions merged within 300 units
(same name match as the restore: case-insensitive, singular/plural; zone-local coords + zone offsets).
- Pre-existing live rows are never dropped; only restored rows (PackageID true165-restored) are.
- Allowed restored rows per group = max(0, cap - live). Kept first: one restored row per radar cluster not already covered
  (no spawn within 400 units), always the closest row/cluster pair; then the remaining slots go to the rows nearest any
  radar position (ties by Mob_ID, deterministic).
- Groups without radar data and groups already within the cap: unchanged. Named uniques were already at 1 (none trimmed).
- Live counts are from AUDIT\fix\coord\run5.db (post-install), every Mob row that is not true165-restored (incl. the
  453 true165-period-new rows).

Result: base AUDIT\fix\stage3\add-restoredspawns165.json 16,838 rows -> 15,761 rows; 1,077 dropped in 59 groups.
The new file simply no longer lists them, so the launcher's stale-row step deletes them; no rule needed.
